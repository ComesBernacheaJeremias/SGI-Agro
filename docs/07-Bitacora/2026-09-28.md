# Bitácora 2026-09-28

## Qué se hizo
- **Se quitó la carga sin conexión** ([[ADR-024-Sin-carga-offline]], reemplaza a [[ADR-006-Offline-limitado]]).
  - Frontend: fuera la cola de pendientes, el caché en IndexedDB, la precarga de maestros, el ingreso sin señal y la búsqueda de productos sin señal. Se borró `src/app/offline/`.
  - Queda: la app instalable, el aviso "Sin conexión" (`app/layout/OfflineBadge.tsx`) y el id generado en el dispositivo (`shared/crud/newId.ts`), que evita duplicados si se reintenta un guardado.
  - Dependencias quitadas: `idb-keyval`, `@tanstack/react-query-persist-client`, `@tanstack/query-async-storage-persister`.
  - Backend: solo comentarios; `test_offline.py` pasó a `test_client_id.py`.
  - Manual: la pregunta "¿Puedo cargar sin señal?" pasó a "¿Y si se corta internet?" (usar datos del celular).
- Documentación actualizada: Offline-y-sincronizacion, Seguridad, Requisitos, Arquitectura, Estructura, Stack, API, Modelo de datos, M03/M04/M05, Puesta en marcha, Manual, CHANGELOG.
- Tests: backend 192, frontend 20 (se fueron los 4 de la cola). Build OK.

## Decisiones tomadas
- Sin carga sin conexión: cubría una parte chica del sistema (no compras, ventas, cobros ni caja), tenía un bug y no se habló con el cliente. Si se corta internet, se usan los datos del celular.
- No hacer planillas Excel para cargar sin señal e importar después: mucho trabajo para un caso rarísimo; se evalúa si el cliente lo pide.

## Problemas / aprendizajes
- El bug: dos `createStore` de `idb-keyval` sobre la misma base IndexedDB (`sgi-offline`) → solo se crea el primer espacio. Los tests (jsdom) no lo detectaban; se vio recién en Chrome. Quedó sin efecto al quitar la función.
